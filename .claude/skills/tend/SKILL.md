# Tend

This repo rots by accumulation. Tend deletes. A run that removes nothing says why in the report.

## Start

`scripts/new-session.sh tend <date>`. Record the human repo HEAD and lead's. Another session running? Work in a git worktree on a branch and fast-forward at the end; leave its uncommitted files alone.

## Passes

In order. Log each removal with its reason before making it. Heavy passes run through `scripts/run.sh -H`, one at a time.

1. **Broken.** `scripts/gate.sh <tree> harness` against the human tree and lead. Red because the human changed behaviour on purpose: update the test, the human code is the spec. Red because the human code is wrong: a finding. BLIND stages get fixed or the harness goes.
2. **Budgets.** Time each gate tier on this machine. Write the numbers, dated, into `INDEX.md` `## Tier budgets`. A tier past its budget gets its slow tests named.
3. **Plants.** Re-apply every plant patch. One that no longer applies, or applies and stays green, is a harness gone blind: fix the plant or the check.
4. **Dead and slow.** Mutation testing over the human code with bot tests as the test command, one candidate file per run. A test that kills no mutant proves nothing: delete it, or sharpen it if its target matters. A slow test that kills nothing a faster one does not goes first. Bounded proofs sit outside mutation tools: plant one break per law; a proof that stays green has a vacuous spec.
5. **Orphans.** A harness with no gate stage or no user: give it a stage or delete it. A generic harness with no subject sat unused until it was deleted; do not keep one "for later". Tests for code that no longer exists, prototypes for a choice the human already made: delete, keep the reason in the doc.
6. **Duplicates.** Two tests proving one thing at one layer. Keep the faster.
7. **Scratch.** `du -sh sessions/*/scratch` against `SCRATCH_BUDGET`. Clear scratch of finished sessions with a fixed path per folder, never a variable-built recursive delete.
8. **Stale numbers.** Baselines older than the code they measure get re-run and re-dated. Counts in docs get regenerated by their script and dated; a typed count goes.
9. **Overturned concepts.** For each overturned decision, grep its concept and wording across `docs/`, harnesses and skills. A doc still teaching it is purged. Docs saying "the human chose" over a provisional `bot` or `human-asked` call get the real status written beside the id.
10. **Docs.** Walk `docs/` per `build-method:hierarchical-context-docs`. Then a read-only agent at `docs/` with the register in hand hunts claims the register does not back.
11. **Intent audit.** Every line in every session's `human.md` since the last Tend: built (where), queued, decided (which id), unruled, or lost. Lost ones go to the roadmap and the report.
12. **Skills.** Findings marked `noise` or `rejected` since the last Tend: a pattern rewrites the skill that produced them. A detector that never confirms anything is a removal candidate. Prune skills to rules, not lesson logs: one clause of evidence per rule, under the `scripts/lint.py` cap; merge or cut before adding.
13. **Memory.** Rules that live only in agent memory files (anything outside git) move into `AGENTS.md`, a skill or a decision.
14. **Index.** Rebuild `INDEX.md` coverage rows from the tree. Paste `scripts/decisions.py stats` with its date into `## Precision`.

## End

Run `finish`. `report.md` lists removed, rewritten and refreshed items with one-line reasons, the old and new tier budgets, and the intent audit's lost lines, so deletion is reviewable.
